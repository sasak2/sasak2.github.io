## 문제 설명

길이가 N이고 벽이 있는 복도에 M개의 공을 던집니다. 공은 벽에 튕겨 반대 방향으로 날아갑니다  
공을 던지는 위치는 0입니다  
공의 속력은 1이고, 공을 새로 던지는 시간(정수)이 각각 주어집니다  
공을 새로 던질 때, 위치 0에는 공이 존재하지 않습니다  
시간 T동안 공끼리의 충돌 횟수를 구하는 문제입니다  
N<=1000, M<=10^6, T<=10^9 입니다

### 2. 비둘기집의 원리와 공의 개수

공을 던지는 시점에, 위치 0에는 공이 없습니다.  
그러므로, 같은 위치에 같은 방향을 향하는 공이 두 개 존재할 수 없습니다.  
(같은 칸, 방향인 두 공은 시작점에서도 같이 있었어야 하므로)  
그렇다면, 각 위치에서의 공의 상태는 4가지 중 하나입니다

1. 오른쪽으로 가는 공이 있다
2. 왼쪽으로 가는 공이 있다
3. 왼쪽과 오른쪽 각각으로 가는 공이 하나씩 있다(서로 부딪혀 있는 상태)
4. 공이 존재하지 않는다.

여기서, 우리는 비둘기집의 원리에 따라 공이 최대 2N개 만큼만 던져질 수 있다는 사실을 알 수 있습니다.  
(위치가 총 N+1개이고, 벽에서는 공이 하나밖에 존재하지 못하므로)

### 3. 공 통과 논리

각 시점마다 공의 배치도를 우리는 길이 N+1의 배열로 표현할 수 있습니다.  
1이면 공이 오른쪽으로 움직이는 중  
-1이면 공이 왼쪽으로 움직이는 중  
0이면 공이 존재하지 않음  
2면 양쪽에서 공이 부딪히는 중  
예를 들어, 사진과 같은 상황은 0 1 -1 0 2 1 -1로 표현할 수 있습니다

![복도 상태를 배열로 나타낸 예시](posts/img/doj40/02.png)

그리고, 우리는 시간을 y축으로 하고, 공의 위치를 x축에 나타낸 그래프처럼 문제 상황을 해석할 수 있습니다

![공끼리 튕기는 시간-위치 그래프](posts/img/doj40/03.png)

한편, 공의 속력은 항상 1입니다.  
공끼리 충돌해도 방향만 바뀌므로, 공이 서로 통과하고 공의 이름만 달라지는 것으로 봐도 됩니다.  
그리고 우리는 충돌 횟수가 중요하지 특정 공의 관계가 중요하지 않으므로, 공의 이름은 신경쓰지 않고, 공이 서로 통과하는 것처럼 해석해도 됩니다.  
그리고 공이 겹치는 상황마다 충돌 횟수를 1씩 늘려주는 방식으로 처리해도 괜찮다는것을 알 수 있습니다.

![공끼리 통과한다고 본 시간-위치 그래프](posts/img/doj40/04.png)

### 4. 루프 발견

그리고, 공이 한 번 왕복하는데 2N만큼의 시간이 걸립니다.

![주기 2N으로 반복되는 루프](posts/img/doj40/05.png)

여기서 우리는 새로운 공을 던지지 않는다면, 복도 상황이 계속해서 반복된다는 사실을 알 수 있습니다! 그리고 반복의 주기는 2N입니다.  
이 그림을 보면 더 직관적으로 알 수 있죠.  
그리고, 각각의 공 궤적이 다른 궤적과 서로 두 번씩 만나므로, 한 번의 루프에서 충돌이 K*(K-1)번만큼 생긴다는 사실도 알 수 있습니다!  
(이 때, K = 현재 복도의 공 개수)

이렇게, 조금의 최적화를 해냈습니다.  
하지만, 항상 루프의 시작에 공이 새롭게 던져지는것이 아니므로, 루프에 속하지 않는 "꼬다리"가 생깁니다.

![N=2에서 루프와 꼬다리](posts/img/doj40/06.png)

그래서 우리는 이 꼬다리를 따로 계산해줘야합니다.

### 5. time table로 꼬다리 구간을 O(N)으로 계산하자

꼬다리를 어떻게 계산하느냐?

루프의 길이 * 복도의 길이 만큼의 크기를 가지는 이중배열과 sum이라는 이름의 배열을 만듭니다.  
즉, 각 시간마다의 복도 상태를 기록하는 테이블과, 각 시간마다 부딪히는 횟수를 기록하는 배열을 만드는겁니다.  
그리고 새로운 공을 던질 때 마다, 새로운 공과 부딪히는 기존의 공 개수를 세서, sum 배열에 더해주면 됩니다.  
이 때, 아까 말했듯이 공을 서로 관통하는 것처럼 다룹니다.

![새 공을 덧그리며 갱신되는 time table과 sum](posts/img/doj40/07.png)

이렇게 하면, 테이블 한 칸에 공을 새로 추가하는데에 상수시간이 듭니다.  
루프의 길이가 2N이므로, 공 하나를 새로 던졌을 때 전체 테이블을 업데이트 하는데에 2N만큼의 시간이 들고,  
이 업데이트를 최대 2N번 하므로 (이 2N번은 공이 새롭게 던져지는 횟수입니다.)  
O(N^2) 만큼의 시간복잡도를 가집니다

이렇게 해서, 꼬다리 부분에서 공이 부딪힌 횟수는 sum배열에서 가져와 answer에 더하고,  
loop에서 계산되는 부분은 sum 전체 합 * loop 반복횟수 만큼 answer에 더하면 됩니다

### 6. sum의 자세한 구현 및 [t,t+1) 구간 정의

우선, 앞에서는 sum 배열을 특정 시간에서 부딪히는 횟수라고 모호하게 정의했지만, 실제로 코드를 짜려면 좀 엄밀하게 정의를 해야됩니다.  
저는 sum[t] = [t,t+1) 구간에서 부딪히는 횟수라고 정의했습니다.

그러면 상태 배열에서 어떤 상황일 때 충돌로 간주해야 할까요?

1. 상태 배열에서 2가 있을 때  
   시간이 바로 t일때 두 공이 충돌한 상황입니다.
2. 오른쪽으로 향하는 공 오른쪽에 왼쪽으로 향하는 공이 있을 때  
   시간이 0.5만큼 지나면 이 둘이 충돌합니다.  
   이 경우, (1 or 2)와 (-1 or 2)가 인접해 있으면 충돌한다고 간주하면 됩니다.

이렇게 두 경우에, 충돌이 일어납니다.

꼬다리를 계산할 때는 새로 넣은 공과의 충돌횟수를 더할 것이기 때문에, 새로 넣은 공의 위치 부분만 조사하여 sum 배열에 더하면 됩니다.

또한, 꼬다리를 계산할 때, 우리가 시간 범위를 [t,t+1) 범위로 잡았으므로,  
계산한 값은 [0,T) 까지의 충돌 횟수입니다  
그러므로 시간이 정확히 T일때의 충돌 횟수도 추가해줘야 합니다.  
time table에서 2의 개수를 세면, 정확히 T일때의 충돌 횟수를 셀 수 있습니다.

### 7. 코드 전문

```cpp
#include <bits/stdc++.h>

using namespace std;

int corridor[2048][1024]={{0,},};
int sum[2048]={0,};
//배열의 크기가 stack의 크기를 넘겨서, 전역변수로 선언한다.

void add_ball(int* position, int direction) {
    /*
    특정 위치에 공을 추가하는 함수, 공 추가하기 이전 위치상태가 0, 1, -1, 2임에 따라서
    1/-1, 2 등으로 바뀐다.
    direction 인자는 추가하는 공의 방향이다.
    */
    if(*position == 0) {
        *position = direction;
    } else if(*position != 2) {
        *position = 2;
    } else {
        //예외상황이 있으면 이 조건분기에 들어오지만, 그럴 일은 없다.
    }
    return;
}

int main() {
    int n, m, t;
    long long int collision=0; //answer
    /*
        loop가 대략적으로 10^6번 일어나고, 충돌은 대략 10^3 * 10^3 번 일어나므로
        값은 대략 10^12, 오버플로우가 일어난다.
        자세한 설명은 8.1절에서 다룬다.
    */

    vector<int> ball_time; //공이 언제 새롭게 던져지는지 저장하는 배열

    //값 입력받는다.
    scanf("%d %d",&n, &m);
    for(int i=0; i<m; i++) {
        int temp;
        scanf("%d", &temp);
        ball_time.push_back(temp);
    }
    sort(ball_time.begin(),ball_time.end());

    //문제에 입력값이 정렬되어서 들어온다는 말이 없어서, 직접 정렬을 해줘야한다.
    //다행히 사이트 내에서 채점용 테스트 케이스를 직접 볼 수 있어서, 정렬을 해야한다는 사실을 깨달을 수 있었다.
    scanf("%d",&t);
    ball_time.push_back(t);
    //뒤의 꼬다리와 loop를 계산하는 로직에서 마지막에는 t까지 계산해야 하므로, ball_time에 t를 넣었다.

    /*
    int corridor[2048][1024]={{0,},};
    int sum[2048]={0,};
    원래 main 함수 내부에 선언했으나, stack 크기를 넘을 수 있어서 전역 변수로 옮겼다.

    corridor[time][위치]
    복도의 공 상태를 나타냄
    0 : 공이 없음
    1 : 오른쪽-> 을 향하는 공이 존재
    -1 : 왼쪽 <- 을 향하는 공이 존재
    2 : 양쪽 다 공이 있음(현재 부딪힌 상태)
    corridor[t][0]이 처음, corridor[t][n]이 끝
    [t][0]에는 무조건 오른쪽->
    [t][n]에는 무조건 왼쪽 <- 공만 존재하도록 하자.

    sum : [t,t+1) 에서 생기는 충돌들
    */

    int time_now = 0;
    
    for(int i = 0; i < ball_time.size(); i++) {
        //일단 corridor에 공을 넣고, 그 다음에 시간에 따라서 collision에 더해보자
        time_now=ball_time[i];
        if(time_now==t) {
            /*
            꼬다리와 loop를 계산하는 로직에서 마지막에는 t까지 계산해야 하므로,
            ball_time에 t를 넣었다.
            그래서 끝나면 break를 하는 조건문이 추가되었다. 
            */
            break;
        }

        //corridor[time_now+j][j]에다가 공을 추가한다
        //물론 j>n일때, 반대로 계산해야한다.
        for(int j=0; j<n; j++) {        
            int* now_adding_balls = &corridor[(time_now+j)%(2*n)][j];
            add_ball(now_adding_balls,1);
            
            if(*(now_adding_balls+1) == -1 || *(now_adding_balls+1) == 2)
                sum[(time_now+j)%(2*n)]++; 
            /* 
            *now_adding_balls는 1 또는 2가 확정이므로, 
            *(now_adding_balls+1)만 확인하면 충돌 여부를 확인할 수 있다.
            이 조건이 맞으면 두 공 사이에 충돌이 발생한다.
            */
               
            if(*now_adding_balls==2)
                sum[(time_now+j)%(2*n)]++;
                
            //또한 *now_adding_balls가 2라면, 한 점에서 충돌이 또 발생한다
        }    
        for(int j=n; j<2*n; j++) {
            int* now_adding_balls = &corridor[(time_now+j)%(2*n)][2*n-j];
            add_ball(now_adding_balls,-1);

            if(*(now_adding_balls-1) == 1 || *(now_adding_balls-1) == 2)
                sum[(time_now+j)%(2*n)]++;
            if(*now_adding_balls==2)
                sum[(time_now+j)%(2*n)]++;
        }

        //이제 loop와 꼬다리를 더한다.
        
        int loop_sum=0;
        for(int j=0; j<2*n; j++)
            loop_sum += sum[j];

        while(time_now+2*n<=ball_time[i+1]) {
            collision += loop_sum;
            time_now+=2*n;
            /*loop 한 번당 loop_sum을 더한다.
            나누기로 계산을 하면 더 빠르다.
            이 while문의 시간복잡도가 O(T/N)으로, T=10^9, N=1인 경우에 실행에 시간이 좀 걸린다.
            이 내용에 관해서는 8.4절에서 자세히 다룬다.
            */        
        }

        while(time_now<ball_time[i+1]) {
            collision+=sum[time_now%(2*n)];
            time_now++;
            //꼬다리 부분을 더한다.
        }
    }

    /*
    T-1까지 했으므로,[0,T) 부분에서의 충돌을 모두 더했다
    정확히 T일때의 충돌횟수는 상태가 2일때이다. 
    즉, 2의 개수를 세면 된다
    */
    for(int i = 0; i < n; i++) {
        if(corridor[t%(2*n)][i]==2)
            collision++;
    }
    
    printf("%lld",collision);

    return 0;
}
```

### 8. 추가적인 자투리 논증

#### 1. 답이 int 범위를 넘어선다.

주석에도 적어놓았습니다.  
loop의 주기는 2000,  
최대 2000개의 공이 존재할 수 있으므로  
한 루프당 4*10^6번의 충돌이 일어날 수 있고,  
T=10^9이므로 루프가 5*10^5번 반복될 수 있습니다.  
그러므로 결과는 2*10^12로, int 범위(2.1*10^9)를 넘어갑니다.

#### 2. 입력값 정렬이 안되어있다.

정말 놀랍게도 발문 어디에도 공을 던지는 시각 t_i가 정렬되어 들어온다는 말이 없습니다.  
당연히 정렬되는줄 알고 제출했다가 틀려서 맞왜틀(맞는데 왜 틀림?) 상태였습니다. ㅋㅋㅋㅋ  
다행히도 채점할 때 쓰는 테스트케이스를 볼 수 있어서 봤더니 입력값이 정렬이 안되어있었습니다.  
그게 아니었으면 평생 왜 틀렸는지 모를 뻔 했습니다. ㅋㅋㅋㅋ

#### 3. corridor 배열의 크기가 stack을 넘는다.

corridor 배열은 4byte 크기의 int 자료형이 2048 * 1024개 있습니다.  
이는 8MB로, 리눅스의 기본 상태 메인 스레드 스택 크기와 같습니다.  
온라인 채점 환경에서는 실행 환경을 알 수 없으므로, 전역변수로 선언하여 정적 메모리 영역에 할당되도록 하였습니다.

#### 4. loop로 반복되는부분을 구하는 방법 구현

사실 나누기를 통해 루프가 반복되는 횟수를 구할 수 있습니다.  
하지만, 루프가 반복되는 횟수를 구하는 식을 세우려면, 코너케이스에서도 잘 작동하는지 세심하게 확인해가며 식을 세워야합니다.  
귀찮아서 그냥 while문을 이용해 여러번 덧셈하는 방식을 사용했습니다. ㅋㅋㅋㅋㅋ

짤 때는 별 문제가 없을것이라고 생각했는데, 이 while문은 약 T/2N번 실행됩니다.  
즉, T=10^9, N=1인 상황에서 5*10^8번 실행이 됩니다.  
CPU가 1초에 러프하게 약 1억(10^8)번 정도 명령을 실행할 수 있는걸 생각하면 TLE가 우려됩니다.  
하지만, 이 while문의 경우, 단순한 덧셈이고, 분기예측 성공 확률도 높기 때문에, 초당 1억번 보다 더 빠르게 실행됩니다.  
VSC 컴파일 및 실행 버튼을 눌러 O0(디버그 모드)로 컴파일 되었을 때 약 1.5초가량 걸렸고,
```cpp
#pragma GCC optimize("O3")
#pragma GCC optimize("Ofast")
#pragma GCC optimize("unroll-loops")
```
옵션을 통해 컴파일을 최적화하고 실행해본 결과 약 0.2초가량 걸립니다.  
(이 옵션에 대한 설명은 [여기](https://justicehui.github.io/etc/2019/08/29/Optimization/)서 확인할 수 있습니다.)  
저는 cpp을 사용하여서 큰 문제가 없었지만, 파이썬 등의 느린 언어를 사용한다면 차이가 생길 수 있습니다.

한편, 온라인 채점 환경에서 최대 실행 시간이 56ms인것으로 보아, N이 작고 T가 큰 상황을 저격하는 케이스가 없었던 것 같기도 합니다.

아무튼, 이 while문을 나눗셈을 이용해 최적화한다면 다음과 같이 적을 수 있습니다.
```cpp
    long long loops = (ball_time[i+1] - time_now) / (2*n); // 루프가 반복되는 횟수
    collision += loops * loop_sum;   // 루프 한 번당 loop_sum
    time_now += loops * (2*n);       // 루프만큼 시간 이동
    //generated by claude 
```

#### 5. 시간 구간 정의와 마지막 시점 충돌 횟수 세기

앞서 sum의 시간 구간을 [t,t+1) 까지로 정의했었습니다,  
반복문을 모두 돌면 [0,T) 범위의 충돌만 계산하여서 시간=T 부분을 더하지 않게 됩니다.  
시간이 정확히 T일 때는, 한 위치에서 두 공이 충돌하였을 때입니다.  
즉, 상태가 2인 위치의 개수를 세서 더하면 됩니다.

[t,t+1)로 시간을 정의한 이유도 있습니다.  
원래는 (t-1,t] 까지 충돌한 횟수로 정의를 하려고 했었는데, 구현을 하는 부분에서 코너케이스가 많이 생기고, 배열도 범위를 넘는 부분을 참조하는것을 방지하기위해 조건문을 더 추가해야 하는 등, 코드가 더러워졌습니다.  
그래서 [t,t+1)로 정의를 바꾸게 되었습니다.

```cpp
#include <bits/stdc++.h>

using namespace std;

int corridor[2048][1024]={{0,},};
//stack 크기를 넘나보네 ㅇㅅㅇ;;
int sum[2048]={0,};

void add_ball(int* position, int direction) {
    if(*position == 0) {
        *position = direction;
    } else if(*position != 2) {
        *position = 2;
    } else {
        //예외상황이 있진 않겠지?
    }
    return;
}

int main() {
    int n, m, t;
    long long int collision=0; //answer
    /*
        loop가 10^6번 일어나고,
        충돌은 최대 10^3 * 10^3 번 일어나므로
        10^12이니까 오버플로우 일어나네
    */
    vector<int> ball_time;

    //값 입력받는다.
    scanf("%d %d",&n, &m);
    for(int i=0; i<m; i++) {
        int temp;
        scanf("%d", &temp);
        ball_time.push_back(temp);
    }

    sort(ball_time.begin(),ball_time.end());
    
    scanf("%d",&t);
    ball_time.push_back(t);

    
    /*
    corridor[time][위치]
    복도의 공 상태를 나타냄
    0 : 공이 없음
    1 : 오른쪽-> 을 향하는 공이 존재
    -1 : 왼쪽 <- 을 향하는 공이 존재
    2 : 양쪽 다 공이 있음(현재 부딪힌 상태)
    corridor[t][0]이 처음, corridor[t][n]이 끝
    [t][0]에는 무조건 오른쪽->
    [t][n]에는 무조건 왼쪽 <- 공만 존재하도록 하자!

    sum : [t,t+1) 에서 생기는 충돌들
    */

    int time_now = 0;
    
    for(int i = 0; i < ball_time.size(); i++) {
        /*
        일단 corridor에 공을 넣고, 그 다음에 시간에 따라서 collision에 더해보자
        */
        time_now=ball_time[i];
        if(time_now==t) {
            break;
        }
        //corridor[time_now+j][j]에다가 공을 추가
        //물론 j>n일때 반사한거 계산해야함
        for(int j=0; j<n; j++) {        
            int* now_adding_balls = &corridor[(time_now+j)%(2*n)][j];
            add_ball(now_adding_balls,1);
            
            if(*(now_adding_balls+1) == -1 || *(now_adding_balls+1) == 2) 
            // nowaddingballs는 1 또는 2가 확정이니까 
            //이 조건이 맞으면 일단 둘 사이에 무조건 충돌함
                sum[(time_now+j)%(2*n)]++;
            if(*now_adding_balls==2)
            //그리고 2면 또 충돌하겠지
                sum[(time_now+j)%(2*n)]++;
            //범위를 좀 넘어갈 수 있지만, corridor를 충분히 크게 선언했고,
            //0으로 초기화되어있으니 괜찮지 않을까
        
        }    
        for(int j=n; j<2*n; j++) {
            int* now_adding_balls = &corridor[(time_now+j)%(2*n)][2*n-j];
            add_ball(now_adding_balls,-1);

            if(*(now_adding_balls-1) == 1 || *(now_adding_balls-1) == 2)
                sum[(time_now+j)%(2*n)]++;
            if(*now_adding_balls==2)
                sum[(time_now+j)%(2*n)]++;
        }
        
        
        //이제 loop꼬다리 더하고, loop가 몇번 반복되냐 따라서 더하고 ㅇㅇ
        /*
        방금 공을 t1에서 던졌으면, 이제 새 공을 t2에 던질 때,
        t1, t1+1 ... t2-1 까지 보면 되네
        
        */
        int loop_sum=0;
        for(int j=0; j<2*n; j++)
            loop_sum += sum[j];

        while(time_now+2*n<=ball_time[i+1]) {
            collision += loop_sum;
            time_now+=2*n;
        }

        while(time_now<ball_time[i+1]) {
            collision+=sum[time_now%(2*n)];
            time_now++;
        }


    }
    //time_now==t에서, 이제 딱 2 갯수만 세면 됨
    for(int i = 0; i < n; i++) {
        if(corridor[t%(2*n)][i]==2)
            collision++;
    }
    
    printf("%lld",collision);

    return 0;
}
```
